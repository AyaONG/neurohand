# PR: NeuroHand — попытки, пары, кольцо и облачная история

Base: `main`. Head: `feature/neurohand-attempts`.

## Описание для PR

Раньше история учитывала базовые успехи локально. Версия добавляет однократные попытки с исходами completed/partial/incomplete/unscorable/cancelled и конкретными метриками, сохраняя прежние счётчики. Legacy-история мигрирует без выдуманного количества попыток и без удаления источника при ошибке.

«Найди пару» использует выбранные пары с большим пальцем, «Обведи кольцо» измеряет экранный путь выбранного кончика через 12 последовательных отметок. Оба режима сохраняют частичные результаты. История фильтруется по упражнению/руке и сравнивает только сопоставимые правила/настройки.

Необязательный Supabase Google PKCE отделяет guest/A/B. Финальная сессия сохраняется локально, отправляется неизменяемым INSERT, подтверждается сверкой ответа; конфликт id требует совпадения полного итога. Очередь переживает reload, повторяет временные ошибки с задержкой, игнорирует ответы прежнего аккаунта. Облачная история загружается страницами, не заменяется локальным массивом. Гостевой импорт явный, JSON-перенос агрегатов отдельный.

Vite/TypeScript, MediaPipe и базовые упражнения сохранены. Новые режимы отключаются независимо через флаги сборки. Видео и поток landmarks в результатах не хранятся.

**Проверки:** 189 тестов в 19 файлах; production-сборка без облачных env; отдельная сборка с выключенными новыми режимами; HTTP 200 и побайтовое совпадение модели/WASM/JS/CSS в preview; шаблонный поиск секретов без находок; git diff --check. Подробности: [отчёт этапа 14](Advanced_Stage_14_Report.md).

**Ограничения:** тесты используют синтетические landmarks и имитации DOM/SDK/транспорта. Настоящая камера, публичный сайт, Google OAuth, Supabase RLS через реальные JWT и второе устройство не проверены. Локальные SQL-тесты не доказывают внешнюю RLS. Не добавлены холодный офлайн/PWA и гарантия одновременной записи нескольких вкладок. При отказе localStorage неподтверждённые данные остаются только в памяти.

## Откат

Предыдущая локально проверенная расширенная база — `eeb9212` (этап 13). До расширения локально проверялась `d14202f` (этап 7, код базовой версии `152e48b`). Это **не** подтверждённые рабочие Vercel deployments; их публичные URL неизвестны.

При проблеме только нового упражнения предпочтительно выключить его флаг и пересобрать текущую версию: формат истории сохраняется. Для общей регрессии выбрать зафиксированное ранее рабочее развёртывание и выполнить Vercel rollback, затем проверить публичную ссылку. Откат переключает опубликованную версию без пересборки; доступные цели зависят от тарифа. [Откат Vercel](https://vercel.com/docs/deployments/rollback-production-deployment)

Frontend rollback не удаляет таблицу, RLS или данные Supabase. Старый базовый frontend до этапа 8 не умеет читать историю v3: она останется в своём ключе, но в старом интерфейсе не появится. Не удалять v3 ради отката и не обещать обратную миграцию. Перед выбором старого deployment проверить совместимость; JSON-экспорт агрегатов хранить отдельно.
