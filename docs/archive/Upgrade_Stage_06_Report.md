## Команды финальной синхронизации — только после ручной проверки и решения публиковать

Из текущего репозитория, оставаясь на `feature/neurohand-product`:

```sh
git status --short
git branch --show-current
git remote -v
git fetch origin
git log --oneline --left-right HEAD...origin/main
git ls-remote --heads origin feature/neurohand-product
```

Если дерево чистое, ветка/remote совпадают с указанными и просмотр новых remote-коммитов не обнаружил конфликтующего изменения, опубликовать именно рабочую ветку:

```sh
git push -u origin feature/neurohand-product
```

При отказе push остановиться и проверить расхождение; не применять force. Для попадания в main открыть PR из `feature/neurohand-product` в `main` и проверить diff. Автоматическое слияние ветки напарника не нужно. Затем настроить статический HTTPS-хостинг **от корня адреса**, проверить локальные `/models` и `/wasm` и выполнить живой маршрут уже на опубликованном адресе. Текущие абсолютные пути не подходят для размещения под `/neurohand/` без отдельной корректировки конфигурации.
