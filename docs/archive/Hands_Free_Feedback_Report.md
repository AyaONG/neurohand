# Автоматический маршрут, обратная связь, PDF и вход

Рабочая база: `40cdd51`, ветка `feature/neurohand-attempts`. Публичная версия из сообщения пользователя — `701dfe0`; её проверка не подтверждает эту локальную сборку. Исходный экспорт пользователя не приложен; описанные цифры не добавлялись в историю.

## A. Маршрут

Новые занятия сохраняют `attempts.flow` версии `hands-free-v1`: отдельные исходы попыток и причины закрытия целей. По умолчанию автоматические переходы включены; ручной режим снимает лимиты повторов/времени. Прототипные параметры: две оценённые неуспешные попытки, две отдельно начатые неоцениваемые попытки, 20 секунд пригодного времени после готовности, после успеха 900 мс обратной связи, затем отдельный переход 3 секунды (для остальных причин переход 3 секунды). Это продуктовые параметры, не медицинские нормы.

Часы цели включают ожидание движения после подготовки; паузы, пропуски кадров, потеря руки, неоднозначность и переходы исключены. Две подряд технически неоцениваемые цели требуют устойчивой видимости с отсчётом. Каждая новая цель вновь проходит подготовку. Пропуск — причина цели, без выдуманной попытки. Счётчики успешных движений не увеличиваются от перехода.

До запуска можно дополнить выбранное занятие базовой программой, выбранными парами и кольцом. Блоки связаны `attempts.route.trainingRunId`, имеют заранее выделенные sessionId; итог блока сохраняется до запуска следующего. Перезагрузка между этими действиями восстанавливает следующий блок, не включая камеру автоматически. Экспериментальные пары требуют явного выбора. Итоги показывают завершённые блоки и фактические успехи.

Схема сессии остаётся v3: новые поля строго проверяются внутри JSON попыток. Старым снимкам связи не добавляются; сравнение учитывает версию переходов, автоматический/ручной режим и маршрут. Существующая SQL-миграция допускает эти вложенные агрегаты; новая SQL-миграция не требуется. RLS и облачный транспорт не изменены.

Проверка A: 223 теста, включая реальные контроллеры с синтетическими кадрами, перезагрузку, удержание жеста, частичные попытки, техническую остановку и конечный базовый маршрут. Камера и публичный сайт этим не проверены.

## B. Обратная связь

Причина отсутствия звёзд: `sparkFlight` создавался только для пинцета, сцена исключала пары и кольцо. Теперь отдельное событие нового финального результата дедуплицируется по attemptId, звезда отображается поверх видео во всех режимах. Completed показывает «Выполнено» около 900 мс, зелёный цвет первые 500 мс. Partial/incomplete показывают наблюдённую метрику, unscorable — причину; награды нет. Текущий сбой видимости имеет приоритет. Reduced-motion отключает движение звезды. Последний результат не обрывается итогами, включая старые сохранённые занятия. Отсчёт не озвучивается каждый кадр.

Проверка B: 229 тестов прошли; покрыты пять типов успеха, повторные кадры, перезагрузка без повторения старых наград, partial с progress=1, сбой и пропуск без звезды.

## C. Отчёт PDF

В итогах добавлен PDF занятия, для нескольких блоков — PDF маршрута; в истории — PDF всей загруженной выборки по датам, упражнению, руке и одинаковым условиям, без ограничения видимой страницы. Не загруженные из облака страницы в отчёт не включаются. JSON остался в «Настройки → Резервная копия и перенос», его проверка/дедупликация не менялись.

Генератор `src/report-pdf.ts` загружается только по запросу и работает в браузере. Зависимости `pdf-lib`, `@pdf-lib/fontkit`; шрифт `public/fonts/NotoSans-Regular.ttf` и свободная лицензия `public/fonts/OFL.txt` поставляются с приложением. История никуда для генерации не отправляется. До асинхронной работы захватывается поколение владельца; после смены аккаунта скачивание старого отчёта отменяется.

Настоящий 4-страничный пример создан тем же генератором тестом `tests/pdf.test.ts` (`NEUROHAND_PDF_SAMPLE=1`), изолированные вымышленные данные отмечены в самом PDF. Все четыре страницы отрендерены PyMuPDF и просмотрены: кириллица, длинные названия, переносы, нумерация и поля читаемы. Проверены пустая выборка, даты/упражнение, неизвестные legacy-попытки и отсутствие внутренних идентификаторов в тексте. Это не реконструкция отсутствующего пользовательского экспорта. Артефакт: `output/pdf/NeuroHand_Report_2026-09-30.pdf`, исключён из Git.

Ограничение: пакет PDF занимает около 1,14 MB до gzip (около 508 KB gzip), но не загружается при обычной тренировке. Первое скачивание без ранее загруженных PDF-модуля/шрифта требует сети; ошибка не удаляет историю.

## D. Вход и внешняя проверка

Исходная ошибка пользователя означает отключённый Google-провайдер, а не отсутствие переменных. **Но текущая реальная read-only проверка 30.09.2026 дала HTTP 200 и external.google=true** для проекта из локальной конфигурации. Текущее включение подтверждено; причина старого ответа не воспроизведена. Возможны изменившаяся настройка либо другой проект в опубликованном bundle. Нельзя объявлять весь вход исправленным по этой проверке.

Добавлена предварительная проверка публичного `GET /auth/v1/settings`: publishable apikey, без токенов/администратора, тайм-аут 4 секунды. Отключённый Google и недоступная проверка дают разные понятные сообщения внутри приложения, без редиректа. Повтор разрешён; запоздавший ответ после смены состояния не запускает вход. PKCE, удаление code перед обменом, изоляция профилей сохранены. После редиректа try/catch SDK уже не может перехватить отдельную страницу ошибки.

Владелец проверяет Authentication → Sign In / Providers → Google, OAuth Client ID/Secret и адреса по [Cloud_Setup.md](../Cloud_Setup.md). Supabase callback: `https://aqrwweayorgzcclwsnje.supabase.co/auth/v1/callback`. Site URL и production-возврат: `https://neurohand.vercel.app/`; разрешённый локальный возврат: `http://127.0.0.1:5173/`. Secret вводится только в Supabase, не в VITE. Публичные источники: [контракт settings](https://github.com/supabase/auth/blob/master/openapi.yaml), [Google OAuth](https://supabase.com/docs/guides/auth/social-login/auth-google).

Новые env не нужны. Прежние: `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`; независимые отключения режимов: `VITE_ENABLE_OPPOSITION=false`, `VITE_ENABLE_RING=false`. Действующая миграция: `supabase/migrations/202609300001_training_sessions.sql`; для этих изменений новая не нужна. Не запускать CREATE TABLE повторно в уже настроенной базе. RLS не отключалась и не менялась.

Поэтому реальная камера, скачивание кнопкой в настоящем браузере, полный Google-вход, два обычных аккаунта/RLS, второе устройство и публичный deployment не проверены. Политики не проверялись от имени администратора вместо пользователей. Push, merge, deploy не выполнялись.

## Финальная проверка и ручная приёмка

Локально: **242 теста / 25 файлов**. Полный набор покрывает guest/auth/profile isolation, очередь/повторы/конфликты, старую историю и новый маршрут. Добавлена интеграционная проверка одного запуска камеры через базовую программу → пары → кольцо: три связанных снимка без повторного запуска камеры. Тайм-аут активного частичного движения сохраняет метрику; повторная подготовка после паузы не расходует лимит. Ручной пропуск начатого движения сохраняет его как отменённое, без включения в оценённые попытки.

`npm run build` и отдельная production-сборка с пустыми `VITE_SUPABASE_URL`/`VITE_SUPABASE_PUBLISHABLE_KEY` прошли; `git diff --check` чист. Vite предупреждает о размерах основного и ленивого PDF-чанков; это предупреждение, не ошибка сборки. Модель и шесть файлов WASM/обвязки присутствуют в dist и не менялись; пороги базовых упражнений не изменены. Сканирование отслеживаемых файлов и production JS по шаблонам secret-ключей, Google Client Secret и приватных ключей не обнаружило совпадений. `.env.local` игнорируется и не отслеживается. Это проверка по шаблонам, не обещание исчерпывающего аудита.

Ручные сценарии (на текущей локальной сборке, не старом публичном сайте):

1. Выбрать пары с большим пальцем, включить автопереходы и добавить кольцо. Один «Начать»: успех → одна звезда/«Выполнено» → отсчёт → следующая цель и затем следующий блок. Удерживать прежний жест через переход: нового успеха быть не должно. Последняя цель должна показать подтверждение до итогов. Проверить reduced-motion.
2. Две отдельные частичные/неполные попытки с раскрытием: ноль выполненных целей, две оценённые попытки, причина «Лимит двух оценённых попыток», автоматический переход. Отдельно partial → completed: одна выполненная цель, две оценённые попытки, одна звезда. Неправильная пара не выполняет цель. В ручном режиме можно повторять без лимита.
3. После подготовки 20 секунд без движения: цель закрывается по времени, попытка не выдумывается. При частичном движении сохраняется наблюдённый результат. Пауза/скрытая вкладка не расходуют лимит; после продолжения нужна подготовка. Перезагрузить во время перехода: цель не засчитывается повторно.
4. Начать два реальных движения и дважды получить длительную неоднозначность: цель «Не удалось оценить», без успеха. Повторить на следующей цели: помощь по видимости и устойчивый отсчёт. Убрать руку: маршрут не прокручивается. При ручной паузе даже хорошая видимость не возобновляет тренировку.
5. Скачать PDF занятия и истории с датами/рукой/упражнением; открыть кириллицу и несколько страниц. Проверить «нет данных» у старых записей и кольцо X/12 с признаком возврата. JSON доступен отдельно. Во время подготовки PDF сменить A → B: отчёт A не должен скачаться. Гостевая история остаётся своей после перезагрузки.
6. Проверить реальный Google-вход и возврат по адресам из Cloud_Setup. После подтверждения входа — обычные аккаунты A/B, RLS и синхронизация на втором устройстве по существующим сценариям; публичный статус «Сохранено в аккаунте» должен подтверждаться сервером. Эти проверки ещё не выполнены.
