# NeuroHand — пошаговый ранбук

Работаете вдвоём: **Человек A** (математика и валидатор) и **Человек B** (камера, экраны, интеграция). Ранбук дополняет `NeuroHand_Build_Guide.md`: там код и обоснования, здесь порядок действий и готовые промпты.

## Правила (нарушение = потерянные часы)

| # | Правило | Зачем |
|---|---|---|
| 1 | **Коммит перед каждым промптом** в Codex | Если Codex сломал файл: `git checkout -- <файл>` и всё как было |
| 2 | Один промпт → одна проверка → один коммит | Не копится невидимых багов |
| 3 | Не идти дальше, пока нет ✅ | Ошибка на шаге 3 найдётся на шаге 9 в 5 раз дороже |
| 4 | Пороги подбираются вручную по debug-цифрам, не Codex-ом | Codex не видит вашу руку |
| 5 | Перед `git push`: `git pull --rebase` | Файлы у A и B разные, конфликтов не будет |

**Как давать Codex файлы.** Codex CLI или облачный Codex с доступом к репозиторию сам читает файлы (запускать `codex` из папки проекта). Если Codex работает в обычном чате: прикрепите `docs/GUIDE.md` и файлы, названные в промпте.

## Шаг 12. Тест на второй руке и подбор порогов (оба)

Каждый человек проходит таблицу из шага 7 и проверку эспандера **на своей руке**. Если у одного из вас порог не работает, подбор ниже.

**Процедура:** нажать `D`, воспроизвести позу, записать значения debug.

| Симптом | Что записать | Как менять константу в `validator.ts` |
|---|---|---|
| Пинцет указательным не засчитывается | максимум `nd(4,8)` при правильном пинцете (M) | `PINCH_CLOSE = M × 1.15` |
| Ошибка пинцета срабатывает при нормальной работе | значения `nd(4,12)` в норме | `PINCH_CLOSE` ниже, чем эти значения |
| Ошибка пинцета не срабатывает | `nd(4,12)` при неверном пинцете (E) | `PINCH_CLOSE = E × 1.15`, но не выше `PINCH_OPEN` |
| Разомкнутый пинцет не считается открытым | минимум `nd(4,8)` при открытой руке (O) | `PINCH_OPEN = O × 0.85` |
| Кулак не считается закрытым | средний `curl` при кулаке (K) и `openCurl` после калибровки | множитель 0.5 в `readGrip` должен быть чуть выше K / openCurl |
| Кулак «не открывается» | средний `curl` при раскрытии (P) | множитель 0.85 ниже P / openCurl |
| Ложная ошибка мизинца | `curl(20)` в кулаке | множитель 0.5 поднять или мизинец жать сильнее |

**Формулы:** порог закрытия = (худшее значение при «закрыто» × 1.15); порог открытия = (худшее значение при «открыто» × 0.85). Между порогами обязан оставаться зазор (это и есть гистерезис). Если пороги сошлись, счётчик снова будет мигать.

После правок: `npm test` (фикстуры должны остаться зелёными), затем ручная проверка на обеих руках. Если фикстуры краснеют после изменения порога, снимите их заново на своей руке, а в тестах поправьте ожидания.

✅ **Проверка:** обе руки проходят таблицу шага 7 и проверку эспандера.
```bash
git add . && git commit -m "tuned thresholds" && git pull --rebase && git push
```
