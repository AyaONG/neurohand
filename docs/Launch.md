# Запуск и демонстрация NeuroHand

Публичный адрес: [https://neurohand.vercel.app/](https://neurohand.vercel.app/). Функции текущих исходников и границы проверок описаны в [README](../README.md). Перед сдачей вручную сопоставьте опубликованную версию с демонстрируемой веткой `feature/neurohand-attempts`.

## Локальное окружение

Из корня существующего репозитория, с Node.js 20.19+ (20.x) или 22.12+:

```sh
npm ci
npm run dev -- --host 127.0.0.1 --port 5173 --strictPort
```

Адрес — `http://127.0.0.1:5173/`. Порт фиксирован: при занятости запуск завершится ошибкой. Разрешите камеру; звук не запрашивается. Для показа выберите базовую программу, затем отдельное короткое занятие с удобными парами большого пальца и кольцо. Шесть пар без большого пальца экспериментальные и по умолчанию не выбраны.

Гостевой запуск не требует env. Если `.env.local` уже существует, не заменяйте его. Для нового окружения образец — [.env.example](../.env.example); облако необязательно. Настройки входа, URL возврата и ключей: [Cloud_Setup.md](Cloud_Setup.md). После изменения `VITE_*` перезапустите dev-сервер или соберите приложение заново.

## Проверка сборки

```sh
npm test
npm run build
git diff --check
npm run preview -- --host 127.0.0.1 --port 4173 --strictPort
```

Preview: `http://127.0.0.1:4173/`. Гостевое хранилище отдельно от 5173 и localhost; приведённый облачный setup разрешает локальный OAuth только на 5173. Не используйте preview как доказательство публикации или качества камеры.

Проверить загрузку `/models/hand_landmarker.task` и `/wasm/vision_wasm_*.{js,wasm}`. Эти файлы копируются из `public` в `dist`; размещение в подпапке не предусмотрено. Наличие файла по HTTP не подтверждает работу GPU/MediaPipe.

## Параметры публикации

| Параметр Vercel | Значение для репозитория |
| --- | --- |
| Root Directory | Корень (`.`) |
| Framework Preset | Vite |
| Install Command | `npm ci` |
| Build Command | `npm run build` |
| Output Directory | `dist` |
| Node.js | 22.x, не ниже 22.12 |
| Production branch | Планируемая `main`; фактическую настройку панели и наличие принятого кода проверить перед выпуском |

Переменные: `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`; независимо отключаемые режимы — `VITE_ENABLE_OPPOSITION=false`, `VITE_ENABLE_RING=false`. Пустые флаги оставляют режимы включёнными. Для полностью гостевой сборки обе Supabase-переменные оставить пустыми. Секреты провайдера Google и service_role не встраивать в приложение.

Порядок: проверить нужную ревизию → применить/сверить миграцию и RLS по [облачной инструкции](Cloud_Setup.md) → проверить env и разрешённые адреса → после принятия кода выпустить новую сборку → проверить публичный URL, камеру, вход, сохранение, PDF и второй аккаунт/устройство. Изменение env не изменяет существующий bundle. Автоматический redeploy старой ветки не добавляет локальные коммиты. Эта инструкция сама не выполняет push, merge или deploy.

## Ручная приёмка перед показом

1. Гостем пройти базовые задания; пауза и потеря руки не прибавляют активное время. Успех и пропуск различаются; последний успех ведёт в итоги после обратной связи.
2. Пары: неправильная пара не выполняет цель, удержание не даёт повторов, раскрытие готовит новую попытку. Кольцо: частичный путь остаётся частичным.
3. Перезагрузить историю, выбрать фильтр и скачать PDF; проверить кириллицу. Отдельно проверить JSON-перенос без дубликатов.
4. Войти обычным аккаунтом, дождаться серверного подтверждения. Проверить офлайн/возврат сети и другой аккаунт без чужой истории; реальный RLS тестировать обычными JWT по облачной инструкции.
5. На втором устройстве войти тем же аккаунтом и загрузить подтверждённую историю. Отдельно проверить Safari и экран 360/768/1440 px; зафиксировать устройство, браузер и фактический результат, а не только факт открытия страницы.
