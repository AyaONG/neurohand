# NeuroHand

Браузерный прототип тренировки движений кисти с веб-камерой. Стек: Vite, TypeScript и MediaPipe Hand Landmarker. Аккаунты и backend отсутствуют; обработка руки выполняется в браузере.

## Что работает

Программа `guided-v1` проходит последовательно, без обязательного выбора вкладок между заданиями:

1. **Собери 5 огоньков:** соединить большой и указательный пальцы. Подтверждённый захват добавляет один огонёк; перед следующим нужно раскрыть пинцет.
2. **Сожми мягкий мяч:** пять сжатий с раскрытием между ними. Размер мяча следует раскрытию кисти; подтверждённое сжатие заполняет сегмент.
3. **Проведи свет в цель:** указатель центра открытой ладони нужно удержать в каждой из трёх целей по две секунды. Закрытая кисть, выход из цели, потеря руки или длинный перерыв между кадрами сбрасывают незавершённое удержание. Выполненная цель повторно не засчитывается.

Подготовка требует пригодной открытой ладони целиком в кадре. Камера зеркальная; Canvas использует физические размеры видеопотока. Завершение всех заданий автоматически открывает итоги. Промежуточные итоги и просмотр прогресса ставят тренировку на паузу; досрочное завершение отмечается отдельно.

Ошибочный захват другим пальцем и неполное сжатие мизинца сопровождаются конкретной подсказкой и красной точкой. Успех — отдельное подтверждение, зелёная подсветка и изменение результата. Открытая ладонь сама по себе не считается ошибкой сжатия.

## Запуск

Требования установленной версии Vite: Node.js 20.19+ в ветке 20.x или Node.js 22.12+. При проверке использовались Node.js 22.13.0 и npm 10.9.2 на macOS; это проверка сборки, не камеры.

```sh
npm ci
npm run dev
```

Открыть адрес из вывода Vite. Выбрать руку, нажать «Начать тренировку», разрешить камеру и показать открытую ладонь. Камера требует localhost либо HTTPS и разрешения браузера. Аудио не запрашивается.

Проверка и production preview:

```sh
npm test
npm run build
npm run preview -- --host 127.0.0.1 --port 4173 --strictPort
```

Preview обслуживает `dist` на `http://127.0.0.1:4173/`. Это локальная проверка сборки, а не публикация. При занятом порте команда завершится ошибкой, не переключившись незаметно на другой origin.

## Модель, WASM и размещение

В репозитории уже лежат:

- `public/models/hand_landmarker.task` — модель;
- `public/wasm/vision_wasm_*.js` и соответствующие `.wasm` — runtime MediaPipe.

Vite копирует их в `dist/models` и `dist/wasm`. `src/camera.ts` использует `/wasm` и `/models/hand_landmarker.task`, режим VIDEO, одну руку и GPU. CDN- и CPU-fallback в этой версии не реализованы. Доступность файлов по HTTP ещё не доказывает работоспособность распознавания на устройстве.

Для публикации нужен статический HTTPS-хостинг, обслуживающий содержимое `dist` от корня адреса. Текущие абсолютные пути не рассчитаны на размещение в подпапке вроде `/neurohand/`. Рабочая опубликованная ссылка пока не подтверждена. Публикация и push в рамках локальных этапов не выполнялись.

## Итоги и «Мой прогресс»

Итоги содержат подтверждённые действия относительно цели, активное время, эпизоды подсказок и лучшее непрерывное удержание. Для не начатых заданий показано «Не начато».

В `localStorage` под ключом `neurohand:progress:v3` сохраняются текущая сессия и до 30 завершённых/остановленных записей. Один id соответствует одной записи. Сохраняются даты, настройки, агрегаты и события попыток, без видео, фотографий и landmarks. Запись происходит по событиям; временные агрегаты — периодически, раз в две секунды между событиями. При аварийном закрытии возможна потеря последнего несохранённого интервала.

История v2 переносится в отдельный ключ v3 после проверки всей записи; исходный ключ v2 сохраняется. У старых записей число попыток неизвестно. Повреждение исходника или ошибка записи не удаляют старую историю.

После перезагрузки предложено продолжить прерванную тренировку или завершить её. Для продолжения нужно снова включить камеру и подготовить руку; пропущенное время и незавершённое удержание не добавляются.

Экран прогресса показывает последнюю тренировку, таблицу с деталями и семь местных календарных дней активности. Сравниваются только две завершённые сессии с одинаковыми явно выбранной рукой, протоколом, целями, настройками и версией распознавания. Неизвестная рука и остановленные тренировки исключены из сравнения. Числа представлены рядом без оценки «улучшения».

Ограничения хранения:

- История принадлежит этому браузеру и origin: схема, хост и порт. `localhost:5173`, `127.0.0.1:5173` и `localhost:4173` имеют разные хранилища. Между устройствами синхронизации нет.
- Очистка данных сайта удаляет историю; приватный режим может не сохранять её после закрытия.
- При отказе хранилища тренировка работает в памяти и показывает предупреждение. При повреждённых данных исходный ключ не перезаписывается; доступные записи показываются, новые результаты остаются в памяти.
- Старый ключ `neurohand-session` сохраняется. Распознанные старые счётчики показываются отдельно без выдуманных дат и настроек и не участвуют в сравнении.
- Одновременное ведение тренировок в нескольких вкладках не поддерживается: используйте одну вкладку для записи результатов.

## Попытки (этап 8)

Попытка начинается после готовности и устойчивого целевого движения. Счётчики базовых упражнений по-прежнему определяются исходными детекторами. В итогах отдельно показаны выполненные, частичные, незавершённые, отменённые и не поддающиеся оценке попытки. Начало, завершение и первое прерывание записываются сразу; агрегаты активной попытки — с прежним интервалом до двух секунд.

Пауза и открытие итогов завершают текущую попытку по наблюдениям; возврат требует новой подготовки. Скрытие вкладки, ошибка камеры и разрыв наблюдения завершают её как `unscorable`, без добавления времени отсутствия. После аварийной перезагрузки сохранённая активная попытка завершается один раз с причиной `reload`, по последнему сохранённому наблюдению. Прогресс до программного порога сам по себе не подтверждает успех.

Новые пороги начала/частичного выполнения находятся отдельно от рабочих порогов пинцета и сжатия. Они требуют проверки шума на реальной камере. Подробные правила и шесть ручных проверок: [отчёт этапа 8](docs/Advanced_Stage_08_Report.md).

## Отладка и реальные примеры

Оба debug-блока и Dump скрыты по умолчанию. Клавиша `D` или `?debug=1` включает отладку. Dump — только явное скачивание во время задания; он не попадает в историю.

Файл содержит время кадра, упражнение, `videoWidth`, `videoHeight`, landmarks и **observedReading** — фактический вывод распознавателя. Это не эталон. Перед добавлением реального случая в тесты нужно вручную проверить метку и записать ожидаемый результат отдельно. Синтетические фикстуры находятся в `tests/fixtures`; их нельзя представлять как реальные тренировки.

## Что проверено

- 101 автоматический тест: геометрия, валидаторы, FSM, программа, сцены, работа обработчиков с имитацией камеры/DOM, локальная история с изолированным хранилищем, сообщения доступности, жизненный цикл попыток и миграция v2 → v3.
- Production build проходит. Preview возвращает HTML, JS/CSS, модель и WASM; содержимое соответствует `dist`.
- Настоящая камера, визуальное отображение в браузере, вторая рука/другой человек и второе устройство **не проверялись в этапе 8**. Нельзя считать синтетические тесты проверкой качества реального трекинга или полной мобильной поддержки.
