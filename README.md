# NeuroHand

NeuroHand — браузерный прототип тренировки движений кисти с обычной веб-камерой. Он превращает наблюдаемое движение в игровые задания, сохраняет полные и частичные результаты и помогает просматривать историю занятий.

**Открыть приложение: [https://neurohand.vercel.app/](https://neurohand.vercel.app/)**

Документ описывает исходники ветки `feature/neurohand-attempts` на базе `139eec4`. Опубликованная сборка может отличаться от локальной ветки; статус проверок указан ниже.

## Возможности

- **Базовая программа:** пять пинцетных захватов, пять сжатий кисти и три цели с удержанием раскрытой ладони по две секунды. Подготовка, подсказки и подтверждение успеха сопровождают каждое задание.
- **«Найди пару»:** выбор из 10 уникальных пар пальцев одной руки, по две цели на выбранную пару в перемешанной последовательности. Шесть пар без большого пальца экспериментальные и включаются явно. Можно выбрать все пары, снять выбор или исключить неудобные. Перекрытие пальцев само по себе не доказывает касание.
- **«Обведи кольцо»:** выбранным кончиком пройти 12 последовательных отметок и вернуться к старту. Измеряется экранный путь; можно двигать всей кистью. Неполный путь сохраняется, например 8 из 12.
- **Маршрут и автоматические переходы:** упражнения можно объединить. После успеха показывается звезда, затем отсчёт 3 → 2 → 1. При включённой автоматике два оценённых повтора без успеха или лимит времени цели позволяют двигаться дальше с частичными результатами; сбои отслеживания учитываются отдельно. Можно остановить занятие вручную.
- **Цели и попытки:** отдельные идентификаторы прохождения упражнения, цели и попытки. Сохраняются полные, частичные, незавершённые, не поддающиеся оценке и отменённые попытки. Пропуск не считается успехом; сбой камеры — не неудача человека. До успеха или закрытия цели повторяется та же цель.
- **Итоги и история:** выполненные/пропущенные цели, попытки до успеха, активное время, пары и отметки кольца. Фильтры по периоду, упражнению и руке; сравнение только сопоставимых настроек и версий правил.
- **Google-вход и Supabase:** необязательный аккаунт, локальная очередь отправки, подтверждённые сервером статусы и загрузка истории страницами. Без облачных настроек доступны гостевые занятия.
- **PDF и перенос:** настоящий PDF с кириллицей доступен в итогах, рядом с заголовком истории и первым в настройках скачивания. Отчёт истории учитывает текущие фильтры и все загруженные записи. Отдельная резервная копия JSON позволяет переносить агрегаты между браузерами.

## Быстрый сценарий демонстрации

1. Открыть приложение, выбрать базовую программу, руку и нажать «Начать тренировку». Разрешить камеру и показать раскрытую ладонь целиком при хорошем освещении.
2. Выполнить пинцет и сжатия с раскрытием между повторами. Для удержания показать открытую ладонь вне круга, переместить внутрь и удержать две измеряемые секунды. Следовать подсказкам готовности между целями.
3. В отдельном коротком занятии «Найди пару» оставить удобные пары с большим пальцем. Затем показать кольцо: пройти отметки по направлению или закончить попытку с частичным результатом. Доступность новых режимов зависит от переключателей сборки.
4. Открыть итоги и «Мой прогресс», показать различие целей и попыток, выбрать фильтр и скачать PDF. Резервная копия JSON находится в закрытом подразделе «Резервная копия и перенос».
5. При доступном входе войти через Google, завершить занятие и дождаться «Сохранено в аккаунте». Сам факт входа не означает отправку результата. Гостевые занятия добавляются в аккаунт только после явного выбора.

## Локальный запуск

Нужны Node.js, совместимый с установленным Vite (20.19+ в ветке 20.x или 22.12+), npm и браузер с камерой. Для воспроизводимого запуска используется порт 5173:

```sh
npm ci
npm run dev -- --host 127.0.0.1 --port 5173 --strictPort
```

Открыть `http://127.0.0.1:5173/`. Без облачных env приложение работает гостем. Для входа используются только `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY` из собственного `.env.local`; пример без значений — [.env.example](.env.example). Существующий `.env.local` не перезаписывать. Secret/service_role и Google Client Secret во frontend не нужны.

Подробности: [запуск и демонстрация](docs/Launch.md), [Supabase, Google и Vercel](docs/Cloud_Setup.md).

## Команды проверки

```sh
npm test
npm run build
git diff --check
npm run preview -- --host 127.0.0.1 --port 4173 --strictPort
```

Preview обслуживает `dist` на `http://127.0.0.1:4173/`; это другой origin, не имеющий общей гостевой истории с портом 5173. OAuth-возврат на 4173 отдельно не настроен приведённой инструкцией. Сборка рассчитана на корень домена, не на подпапку.

## Стек

TypeScript, Vite, MediaPipe Hand Landmarker, Canvas, SVG/CSS; Vitest для тестов. Supabase JS SDK обеспечивает Google Auth (PKCE) и доступ к PostgreSQL с RLS. PDF создаётся в браузере через pdf-lib и fontkit со встроенным шрифтом Noto Sans.

Модель и WASM находятся в `public/models` и `public/wasm`, загружаются с текущего сайта. Распознавание выполняется в браузере, для одной руки, с GPU. Аудио не запрашивается; CPU/CDN fallback не реализован.

## Хранение данных

Гость сохраняет текущую тренировку и историю в `localStorage` своего браузера/origin. У аккаунтов отдельные локальные хранилища и очереди. Финальная сессия отправляется одной неизменяемой строкой в `public.training_sessions`; повторная отправка не создаёт копию, конфликт проверяется по содержимому. RLS ограничивает SELECT/INSERT владельцем, UPDATE/DELETE клиенту не разрешены. Это реализованная модель защиты, а не заявление об успешно проведённой проверке двух реальных пользователей.

Хранятся даты, настройки, агрегаты и результаты попыток, **без видео и потока landmarks**. История показывается страницами по 30 записей; это не лимит хранения, неподтверждённые записи не удаляются из-за размера страницы. Старым данным не приписываются неизвестные попытки или связи с целями; исходные данные сохраняются при ошибке миграции.

Очередь переживает перезагрузку, временные сетевые ошибки повторяются с задержкой. При отказе `localStorage` показывается предупреждение: неподтверждённые данные только в памяти могут пропасть после закрытия страницы. Гостевые данные не переносятся автоматически в аккаунт, с localhost на публичный сайт или на другое устройство. Для переноса нужен JSON и явный импорт. PDF предназначен для чтения, не восстановления.

## Проверки и ограничения

**Реализовано:** перечисленные выше функции доступны в исходниках; новые режимы можно независимо отключать через `VITE_ENABLE_OPPOSITION=false` и `VITE_ENABLE_RING=false` с новой сборкой. Базовая программа остаётся доступной.

**Автоматически проверено на версии `139eec4`:** 262 теста в 26 файлах, TypeScript/Vite production-сборка и `git diff --check`. Проверяются контроллеры, геометрия, попытки, миграции, очередь, изоляция аккаунтов на имитациях SDK/DOM, PDF и JSON. Сборка выдаёт предупреждение о размере JS-чанков. Изменение этой документации не добавляет новой проверки камеры или облака.

**Проверка ссылок при подготовке документации (30.09.2026, до выноса архива):** 51 внутренняя Markdown-ссылка разрешалась в существующий файл; 17 уникальных внешних адресов, включая сайт и репозиторий, ответили HTTP 200. После выноса архива внутренние ссылки оставшихся документов проверены повторно. HTTP-проверка доступности не заменяет браузерную приёмку.

**Сведения о ручной проверке:** владелец сообщил о работающем Google-входе и двух сохранённых занятиях в локальном приложении на `127.0.0.1`. Это ограниченное подтверждение пользовательского сценария, не проверка реального RLS двумя аккаунтами, второго устройства или совпадения публичной версии с веткой. Агент в последнем цикле исправлений проверял SDK/DOM на имитациях, без подключённого браузера.

**Требуют ручной приёмки:** качество трекинга реальной камеры и экспериментальных пар, удержание при шуме, Safari/PDF, ширины 360/768/1440 px, второй аккаунт и второе устройство. Поддержка всех телефонов и браузеров не заявляется. Нужны разрешение камеры, защищённый контекст (HTTPS либо локальный адрес), подходящий GPU и освещение. Один браузерный сеанс записи за раз; параллельные тренировки в нескольких вкладках не поддерживаются.

Метрики описывают выполнение программных заданий, не физическое касание и не изолированную подвижность пальца. NeuroHand — прототип, не медицинское устройство: диагнозы, клиническая эффективность и «процент восстановления» не заявляются. Debug включается отдельно (`D` или `?debug=1`); явный Dump может скачать снимок landmarks для отладки, но не входит в обычную историю или облачную очередь.
